# Frontend Design Skill

This skill guides creation of distinctive, production-grade frontend interfaces that avoid generic AI aesthetics. Implement real working code with exceptional attention to aesthetic details and creative choices.

Use this skill whenever design is happening in code:
- web components,
- pages,
- applications,
- interactive explainers,
- dashboards,
- calculators,
- games,
- visualizations,
- HTML/CSS/JavaScript artifacts,
- React, Vue, Svelte, or similar UI work.

When another skill owns the task, such as `show-me-infographic`, use `frontend-design` as a design-quality guideline. It improves visual direction and polish; it does not override the other skill's domain logic, factual requirements, output format, or workflow.

## Design Thinking

Before coding, understand the context and commit to a clear aesthetic direction:
- Purpose: What problem does this interface solve? Who uses it?
- Tone: choose a specific direction such as brutally minimal, maximalist, retro-futuristic, organic, luxury/refined, playful, editorial, brutalist, art deco, soft/pastel, industrial, utilitarian, clinical, academic, technical, or another context-specific direction.
- Constraints: framework, performance, accessibility, responsiveness, and environment.
- Differentiation: what makes this interface memorable and clearly designed for this exact context?

Choose a clear conceptual direction and execute it with precision. Bold maximalism and refined minimalism can both work. The key is intentionality, not intensity.

Then implement working code that is:
- production-grade and functional,
- visually striking and memorable,
- cohesive with a clear aesthetic point of view,
- refined in spacing, typography, colour, motion, and interaction details.

## Frontend Aesthetics Guidelines

Focus on:
- Typography: choose fonts and type scales that fit the interface's purpose. Avoid defaulting to Arial, Roboto, Inter, or generic system typography when a more distinctive choice is available and appropriate.
- Colour and theme: commit to a cohesive aesthetic. Use CSS variables for consistency. Dominant colours with sharp accents are usually stronger than timid, evenly distributed palettes.
- Motion: use animations for effects and micro-interactions when they support meaning. Prefer high-impact moments, staged reveals, useful transitions, and hover/focus states that clarify interaction.
- Spatial composition: use purposeful layouts. Consider asymmetry, overlap, diagonal flow, grid-breaking elements, generous negative space, or controlled density when the concept benefits from it.
- Backgrounds and visual details: create atmosphere and depth instead of defaulting to flat solids. Use contextual texture, subtle grain, geometric pattern, layered transparency, dramatic shadow, or decorative borders only when they support the aesthetic.

Avoid generic AI-generated aesthetics:
- overused font choices,
- purple gradients on white backgrounds,
- predictable hero/card/component patterns,
- cookie-cutter layouts,
- decoration that is not connected to the subject,
- designs that could fit any prompt after changing only the title.

Vary between light and dark themes, type choices, layout systems, palettes, and aesthetic directions. Do not converge on the same look across generations.

## Complexity Match

Match implementation complexity to the aesthetic vision:
- maximalist designs need richer code, layered effects, and stronger motion discipline,
- minimalist designs need restraint, precise spacing, excellent typography, and subtle interaction,
- utilitarian tools need density, clarity, predictable controls, and low-friction workflows,
- educational visuals need legibility, semantic colour, and concept-first composition.

Elegance comes from executing the chosen vision well.

## Quality Checks

Before finalizing, verify:
- the interface has a clear aesthetic point of view,
- the visual decisions fit the topic and audience,
- controls and states are functional,
- typography and spacing are deliberate,
- colours have semantic or atmospheric purpose,
- responsive layouts do not overlap or break,
- the design would not look unchanged for an unrelated prompt.
